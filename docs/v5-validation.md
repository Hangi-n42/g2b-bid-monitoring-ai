# v5-F 변경·비교·검증 기록

작성일: 2026-09-18. 사용자가 오늘 v5 제작과 DACON 제출을 명시적으로 요청했다. 맥 이전과 실제 모델 실험은 내일로 미뤘다.

## 이번 제출의 의미

실제 고정 Gemma dev 예측은 확보하지 못했다. 따라서 항목별 TP·FP·FN, 후보별 실제 F1 비교, 효과가 확인된 변경만 결합하는 단계는 **미실행**이다. mock 결과를 F1로 채점하지 않았다. 오늘 제출은 기존 전문가 계획의 첫 후보인 **B그룹 사실 출력 변경을 평가하는 공식 실험**이다. 성능 향상이 검증된 최종 조합이라는 의미가 아니다.

## 변경

- `submission_v5/`를 별도로 만들었고 기존 `submission/`과 v4 ZIP은 보존했다.
- ZIP의 여섯 파일 중 변경 파일은 `script.py` 하나다. 법령 가이드, 사례, 원문 선택기는 v4와 바이트 단위로 같다.
- B그룹(v10~18)은 동일 요청에서 `facts`를 먼저 생성한 뒤 기존 아홉 판정을 출력한다. 필드는 법체계, 실제 조달유형, 금액 종류의 관측 상태, 경쟁제품 일치의 역할, 영리기업 범위, 예외 범위, 기업규모 자격, 직접생산 자격이다.
- 각 사실은 제한된 state와 현재 요청의 S번호 또는 명시된 meta 키를 가진다. 미상·상충·서류 언급만·발췌에서 미관측을 구별하도록 지시한다. 사실값으로 최종 라벨을 자동 덮어쓰지 않는다.
- 기존 v4 방식으로 입력을 먼저 확정한 다음 B 지시만 추가한다. 새 지시 때문에 기존 원문이나 사례가 삭제되지 않는다. 기존 입력 예산 외에 지시용 1,536토큰 상한을 예약한다.
- A/C의 입력·출력 형식과 512 출력토큰 상한은 유지한다. B 출력 상한만 512→768이다. 기본 호출 수는 공고당 세 번이다.
- 사실의 출처 검사, B 전용 재시도 지시, 재시도 컨텍스트 한도 검사를 추가했다. 잘못된 응답을 전부 정상 라벨로 대체하지 않는다.
- 전체 관측 범위는 기존 입력 상태 정보와 지시로 다룬다. 계획의 `observation` 별도 출력 및 정확한 금액값 출력은 이번 최소 후보에 포함하지 않았다.

고정 토크나이저 입력 합계는 v4 3,486,071 → v5 3,593,871이다. 증가분 107,800토큰은 B그룹 200요청 × 539토큰이다. 실제 생성량이나 서버 시간 증가율을 뜻하지 않는다. 합성 출력은 형식 길이 검사용이며 실제 공고의 추출 사실·정답이 아니다.

테스트 과정에서 로컬 테스트 모듈의 import 설정을 수정했다. Windows embedded Python은 스크립트 폴더를 자동 검색하지 않아 smoke 실행에 명시적 sys.path를 사용했다. 서버 제출 코드에 Windows용 경로나 실행 우회는 추가하지 않았다. 최종 프로파일의 코드·자산 해시가 실행 전후 동일함을 확인했다.

## 남은 위험과 내일 비교

모델이 잘못된 사실을 먼저 생성하면 최종 판정도 그 오류를 따라갈 수 있다. 유효한 S번호라는 검사는 의미상 올바른 근거라는 증명이 아니다. source enum의 meta 키 존재·사실 지지 여부도 의미 검사까지 보장하지 않는다. B 출력 증가에 따른 생성 지연·종료 오류·서버 구조화 디코딩은 실제 런타임으로 확인해야 한다.

오늘 결과로 비교할 수 있는 것은 v4 대비 B 사실 출력 **지시+출력 형식+출력 예산 묶음**의 리더보드 변화다. 이 세 요소의 단독 인과효과, B 내부 항목별 TP/FP/FN 변화는 점수 하나로 확정하지 않는다. A/C 코드·입력이 같아도 서버 실행의 완전한 출력 동일성을 보장하지 않는다.

내일 실제 모델 환경에서 v4/v5-F를 동일 입력과 검색 제외 fold로 비교한다. 이후 자격 문맥 보충(C), 사례 검색 개선(R)을 독립적으로 평가하고 효과가 확인된 조합만 만든다. 현재 공개 dev는 설계에 이미 활용됐으므로 완전 미관측 일반화 평가로 표현하지 않는다.
